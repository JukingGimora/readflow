## 1. 要做成什么

很多业务系统的查询藏在三级菜单里，不熟悉电脑的人不会用。目标是让人**说一句话就查到**，并且换一个系统只换图谱、不换代码。

分三层，职责不要混：

| 层 | 谁做 | 在哪跑 | 做什么 |
|---|---|---|---|
| 探索 | 外部大模型 | 外部，一次性 | 摸清一个系统，产出符合标准的图谱文件 |
| 运行（本仓库） | 确定性程序 + 本地小模型 | 自己的服务器 | 校验并加载图谱；登录接力；按图谱只读取数；多轮回答 |
| 语音 | VoiceLab | 同一台服务器 | 识别、合成、会话；把文字转给运行层 |

当前阶段只做**原子层**：一个系统、一张图谱、一段多轮会话、只读。

## 2. 数据流

**探索到上线（一次性）**

```
外部模型 + 一个账号 ──探索──▶ systems/<id>/graph.json + 探索报告
                                     │ 导入
                                     ▼
                     运行层校验（graph-spec 第 8 节）──通过──▶ 可用
```

**一轮问答（运行时）**

```
用户说话 ─▶ VoiceLab 识别(8040) ─▶ POST /voice/handle {heard, context.state}
                                         │
                    1. 听懂：一句话 → 能力 + 词槽（规则认关键词和词槽；业务类别认不出时问本地模型）
                    2. 规划：能力 → 取数来源（缓存 → 接口）
                    3. 取数：带该用户的会话调只读接口；过只读检查
                    4. 计算：过滤、求和、分组（程序算，不经过模型）
                    5. 回答：模板 + 后续问题
                                         │
用户 ◀─ VoiceLab 合成 ◀─ {reply, state_patch, followups}
```

浏览器页面 `/desk` 走同一条路，只是入口是 `/desk/api/query`，状态由页面每轮回传。

**登录接力**

```
会话过期 ─▶ 运行层按图谱 auth 重新登录
              ├─ 图片验证码：先自动识别；失败 ─▶ 原图给用户 ─▶ 用户输入 ─▶ 原样填回
              ├─ 短信码：提示用户 ─▶ 用户输入 ─▶ 原样填回（实时）
              └─ 滑块 / 扫码：把那块画面给用户操作        ← 未实现，见 T6
```

## 3. 部署现状（2026-11-20 晚实地查看）

- 服务器：一台 4090 D。VoiceLab 四个服务只监听本机：编排 8040、识别 8030、合成 8031（按需启动）、本地模型 8050（llama.cpp，Qwen3；VoiceLab 文档写的是 4B-Q4）。
- 运行层：`~/projects/snxt-query`，systemd 用户服务 `snxt-query`，端口 8790。**2026-11-20 19:37 已部署本分支**（含 T0 登录门）。部署前的版本备份在 `~/projects/snxt-query-backup-20261120-1937.tgz`。
- 口令：`.env` 里 `QFLOW_TOKEN`（接口用）和 `QFLOW_DESK_PASS`（页面用，一句中文）。部署脚本不再覆盖已有的 `.env`。
- VoiceLab 里登记为 agent `snxt_deduction`，`type: http`，指向 `/voice/handle`，登记的口令已和服务一致。
- 部署方式：在开发机上运行仓库外的 `deploy_server.sh`（打包 → scp → 解包 → 重启服务 → 向 VoiceLab 注册 agent）。

**部署后实测通过的**：不带口令访问 `/desk/api/*` 返回 401；页面口令能登录并查询；用 VoiceLab 登记的口令按它的请求格式连问两轮（含追问）正常。

- （已解决，2026-11-20 20:05）`flow.tradesitecloud.com` 曾有一半请求 404：服务器上有两个 cloudflared 进程连同一条隧道，其中 11-02 手动启动的那个是旧配置。经负责人同意已停掉，现在只剩 systemd 用户服务 `cloudflared-jukinggimora`。**以后改隧道配置只重启这个服务，不要再手动起进程。**

## 4. 已经做了的

- 浅色会话页：语音球、输入框、示例问法；回答是一句结论 + 图或表 + 可点的后续问题；过程默认收起。
- 多轮：每轮回传状态，「那 12 月呢」「明细呢」「那发货呢」可连续追问；没听懂不清空上下文。
- 图谱里的能力带 `examples` / `followups` / `metrics`，页面和语音都从图谱读，页面不写死业务词。
- 管理页：节点连线图谱、导入外部图谱并校验、服务现状。
- 只读检查接到了真正发往业务系统的请求上。
- 页面登录门（T0）：设了 `QFLOW_TOKEN` 后 `/desk/api/*` 全部要鉴权；页面用口令换当天有效的签名 cookie，输错有次数上限。
- 清掉了本地探索、浏览器抓取、假的「生成系统」接口、写死的账号兜底、过期文档。
- 定了图谱标准 v1 和给外部模型的探索说明（**只有文档，运行层还没按它实现**）。
- 图谱校验器（T1）：`qflow/spec.py`，`python -m qflow validate`。格式示例见 `docs/examples/graph-example.json`（虚构系统，只说明格式）。

**T0 留下的缺口**

- 会话是「一个口令、所有人同一个会话」，只解决「能不能进」，不区分是谁。按人区分是 T4 的事。
- 输错次数记在内存里，重启清零；会话当天有效，过了零点要重新输入。
- 页面口令现在是一句固定的自然语言（`QFLOW_DESK_PASS`），比对时忽略空格、标点和全半角。
- **每天换口令、一次性链接、对着手机念口令：已定和 T4 一起做，不单独做。** 参考实现在服务器 `~/projects/future/assistant/`（`passphrase.py` + `door.py`）：口令形如「地瓜地瓜我是土豆」，每天由本地模型生成、机械校验（两到三字名词、两个词不能同音近音）、连同一次性链接发邮件；**答对哪条口令就是哪个账户**，这正是 T4 要的「口令即身份」。那边用 MySQL，`~/projects/me/me/door.py` 是它的 SQLite 单用户改写版。搬的时候需要：邮件发送配置、定时任务、本地模型地址。

**T3 第一步的实测（2026-11-20，服务器上的 Qwen3-4B-Q4_K_M，`/no_think`、温度 0、只答一个字母）**

可重跑：`QFLOW_LLM_URL=http://127.0.0.1:8050/v1/chat/completions python scripts/eval_understand.py`，用例在 `tests/understand_cases.json`。走的是线上同一条路（`voice.handle`）。

| 批次 | 句数 | 纯规则 | 规则 + 模型 |
|---|---|---|---|
| 调提示词和规则时用过的 | 78 | 44 | 72 |
| 追问（带上一问） | 15 | 10 | 14 |
| 图谱自带的示例问法 | 11 | 10 | 11 |
| 定稿后才加、从没用来调过的 | 21 | 13 | 19 |
| 合计 | 125 | 77 | 116 |

每句中位数约 140 毫秒（经 SSH 转发测的，服务器本机约 70 毫秒）。

实测得出的分工（写代码前先看这段，不要把更多事情交给模型）：

- 模型擅长：一句口语想查哪一类业务。模型单独判断 104 句对 97 句。
- 模型不擅长：① 要总数还是要明细（明显偏向明细，64 句错 20 多句）；② 抽时间词（会漏「今年」「本月」，还编过一个）。这两件事归规则。
- 模型分不清「想办事」和「想查的东西这里没有」。试了五种提示词写法，结果都在 97–99/104，是噪声，所以没有继续调，而是让两种情况共用一句对两边都成立的回答。
- 规则认出业务关键词时用规则，模型只保留一票否决（它说「想办事」就拒绝）。
- 模型没配、超时、答非所问时退回纯规则，30 秒内不再重试。

剩下的 9 句错：6 句是上面说的「这里查不了」被判成「想办事」（回答仍然成立）；「扣了罚款我还剩多少货款」规则按关键词判成扣款，应为对账；「今天天气不错」在有上文时因为带「今天」被当成追问；「前天送的货到了没」给了汇总，应为明细。

顺带修了规则里一个会答错数的 bug：「去年十一月」原来被当成「去年全年」，「十月份」「上礼拜」完全不认。现在汉字月份和日期、「三月到五月」、上下半年都认。
