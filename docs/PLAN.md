# 计划书：现状、缺口、下一步

给接手的人或 code agent 看。先读这一份，再读 [`graph-spec.md`](graph-spec.md) 和 [`explorer-brief.md`](explorer-brief.md)。
改了代码就同步改这里的状态，否则没人知道缺口在哪。

最后更新：2026-11-23

## 1. 要做成什么

很多业务系统的查询藏在三级菜单里，不熟悉电脑的人不会用。目标是让人**说一句话就查到**，并且换一个系统只换图谱、不换代码。

**一条硬规矩：这个仓库里不允许有为某一个系统专门写的代码。** 某个系统特有的东西（接口、字段、关键词、检测项目的叫法、单号格式、登录页长什么样）只能写在它的图谱里。发现要为某个系统加 `if`，说明标准缺了一块，去补标准（`graph-spec.md`），不要补代码。2026-11-23 已按这条把圣农专用的代码全部删掉（见第 4 节）。

三层，职责不要混：

| 层 | 谁做 | 在哪跑 | 做什么 |
|---|---|---|---|
| 探索 | 外部大模型，或人用浏览器开发者工具 | 外部，一次性 | 摸清一个系统，产出符合标准的图谱文件 |
| 运行（本仓库） | 确定性程序 + 本地小模型 | 自己的服务器 | 校验并加载图谱；登录；按图谱只读取数；多轮回答 |
| 语音 | VoiceLab | 同一台服务器 | 识别、合成、会话；把文字转给运行层 |

**原子 agent**（`qflow/agent.py`）：一个系统 = 图谱 + 账号 + 登录态，对外三个动作：登录、执行一个能力、听懂一句话后执行。输出是同一种结构（`qflow/runner.py` 的 `run` 返回值）。
以后的多系统串联、并联（先在 A 查，再去 B 查，最后汇总）在这一层之上做：按顺序或同时调用几个 agent 的「执行」，agent 本身不改。这一层还没做（G4）。

## 2. 数据流

**接入一个新系统**

| 步骤 | 谁做 | 现状 |
|---|---|---|
| 1. 探索系统，写出图谱 | 外部模型按 `explorer-brief.md` 做；没有外部模型时人照着 `graph-spec.md` 写 | 可以做 |
| 2. 校验：`python -m qflow validate <文件>`，或在页面「管理 → 导入图谱」里粘贴 | 本地 | 可以做 |
| 3. 导入：页面导入后存到 `data/systems/<id>/graph.json`；随仓库发布的放 `systems/<id>/graph.json` | 本地 | 可以做 |
| 4. 在页面上填这个系统的账号密码（存服务器，权限 600，不回传） | 用户 | 可以做 |
| 5. 登录（见下） | 本地，必要时人接手 | 可以做（假系统上验证过；真实圣农还没验证） |
| 6. 说话就能查 | 本地 | 可以做（接口规整的系统） |

运行时不需要外部模型。本地模型不在线时退回规则。数字从不经过模型。
接口不规整的系统（请求带前端现算的签名、数据直接写在页面里）第 1 步就会卡住，是缺口 G1。

**一轮问答**（页面 `/desk/api/query`、语音 `/voice/handle`、接口 `/query` 是同一条路）

```
一句话 ─▶ agent.ask（qflow/agent.py）：多个系统时先选系统（谁的关键词对上问谁，否则接着上一问的系统）
        ─▶ ask.ask（qflow/ask.py）
             1. 查哪一类：图谱里的关键词、枚举值、单号格式；都对不上时问本地模型（只答一个字母）
             2. 汇总还是明细、时间、枚举值、单号：规则（timewords.py + 图谱里的 values / synonyms / pattern）
             3. 追问：沿用上一问的条件，新说的覆盖旧的
        ─▶ runner.run：按图谱发只读请求 → 翻页 → 取字段 → 过滤 → 求和分组 → 套回答模板
        ─▶ view.answer：整理成页面和语音用的样子（数字、表头、「怎么查的」都来自图谱）
```

登录态失效时：能无人值守登录的系统（没有验证码，或验证码能自动识别）自己登录后重试一次；否则回答「需要重新登录」，页面自动弹出登录。

**登录**（`qflow/login.py`，照图谱 `auth` 一节走，两级）

```
打开 login_url
  ├─ 自动：按 steps 填保存的账号密码
  │     ├─ 没有验证码 ─▶ 提交
  │     └─ 图片验证码 ─▶ 自动识别（最多 3 次）─▶ 认不出就把图发到页面，人输入
  └─ 窗口（兜底）：滑块、扫码、短信、第三方登录，或者自动那一级走不通
        ─▶ 把服务器上这个浏览器的画面显示在页面里，人直接点、拖、输入
成功的判断：auth.success（没写就按「不在登录页了」推断）＋ 用取到的 cookie 真调一次接口
成功后：存登录态，关浏览器。之后的查询是纯 HTTP，不开浏览器。
```

## 4. 已经做了的

- 通用执行器 `qflow/runner.py`：读图谱 → 发请求 → 翻页 → 按 `map` 取字段 → 去重 → 本地过滤 → `compute` → 按 `answer` 回答。只执行 `access: read` 的 `http` 操作，发请求前过只读检查（`qflow/online.py`）。
- 听懂一句话 `qflow/ask.py` + `timewords.py` + `understand.py`：全部读图谱；本地模型只做一道选择题，连不上就退回规则。
- 原子 agent `qflow/agent.py`：图谱注册表、账号、登录态、同一请求 120 秒内不重复发、登录态失效的处理。
- 通用登录 `qflow/login.py` + `browser.py`：自动填表、图片验证码（识别或人填）、浏览器窗口兜底。
- 服务 `qflow/service.py`：页面、语音、`/query` 一条路；口令门（设了 `QFLOW_TOKEN` 后所有接口要鉴权，页面用口令换当天有效的 cookie，输错有次数上限）。
- 页面 `qflow/web/index.html`：问答；需要登录时自动弹出账号 / 验证码 / 浏览器窗口；管理页看图谱、导入图谱（校验用服务端同一套规则）。
- 图谱校验器 `qflow/spec.py`：`python -m qflow validate`。
- 圣农图谱 `systems/sunner_srm/graph.json`：29 个菜单页里只有「质量扣款明细」能查（扣款汇总、扣款明细），其余 28 个标了「还没有探索」。
- **删掉的圣农专用代码**（2026-11-23）：Excel 导入和本地库（`importer.py`、`db.py`、`engine.py`）、写死的 6 类查询和回答（`capabilities.py`、`answer.py`、`voice.py`）、圣农关键词和检测项目名（`nlu.py`）、圣农登录脚本（`srm.py`、`srmlogin.py`、`srmapi.py`、`authbridge.py`）、扣款内存快照（`livequery.py`）、旧格式图谱（根目录 `graph.json`、`qflow/graph.py`、`systems/sunner_srm.json`）。

**验证到了哪一步**

- 假系统「小店订单」（`tests/fakesite.py`，一个真的本地 HTTP 服务：登录页带图片验证码 + 要登录才能调的分页接口，和圣农毫无关系）：只给它一份图谱，不改代码，登录、取数、问答、追问全部跑通。自动化测试里用真的 Chrome 跑过登录（验证码交给人、浏览器窗口里点和输入）；页面上手动走过一遍：提问 → 弹出填账号 → 验证码 → 登录成功后自动重问 → 出结果；以及浏览器窗口登录。
- 圣农：执行器发出的请求和 2026-11-18 浏览器抓包一致；带过期登录态真实调用，返回 401，被正确识别为失效。**带有效登录态拿到真实数据、按图谱自动登录圣农，这两件都还没验证。**

## 6. 标准层面的缺口

见 [`graph-spec.md` 第 10 节](graph-spec.md)，编号 G1–G8：页面读取、写操作、下载、跨系统、多接口串联、过期检测、动态参数、大数据量。
G1（从页面读数据、请求签名）是做电商比价的前提；G5（一个能力用多个接口）是圣农对账的前提；G2 + G4 是「系统 A 填表、系统 B 汇总」的前提。
