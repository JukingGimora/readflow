最后更新：2026-11-20

## 1. 要做成什么

很多业务系统的查询藏在三级菜单里，不熟悉电脑的人不会用。目标是让人**说一句话就查到**，并且换一个系统只换图谱、不换代码。

分三层，职责不要混：

| 层 | 谁做 | 在哪跑 | 做什么 |
|---|---|---|---|
| 探索 | 外部大模型 | 外部，一次性 | 摸清一个系统，产出符合标准的图谱文件 |
| 运行（本仓库） | 确定性程序 + 本地小模型 | 自己的服务器 | 校验并加载图谱；登录接力；按图谱只读取数；多轮回答 |
| 语音 | VoiceLab | 同一台服务器 | 识别、合成、会话；把文字转给运行层 |

当前阶段只做**原子层**：一个系统、一张图谱、一段多轮会话、只读。

## 2. 数据流

**探索到上线（一次性）**

```
外部模型 + 一个账号 ──探索──▶ systems/<id>/graph.json + 探索报告
                                     │ 导入
                                     ▼
                     运行层校验（graph-spec 第 8 节）──通过──▶ 可用
```

**一轮问答（运行时）**

```
用户说话 ─▶ VoiceLab 识别(8040) ─▶ POST /voice/handle {heard, context.state}
                                         │
                    1. 听懂：一句话 → 能力 + 词槽（规则优先，不中再问本地模型）
                    2. 规划：能力 → 取数来源（缓存 → 接口）
                    3. 取数：带该用户的会话调只读接口；过只读检查
                    4. 计算：过滤、求和、分组（程序算，不经过模型）
                    5. 回答：模板 + 后续问题
                                         │
用户 ◀─ VoiceLab 合成 ◀─ {reply, state_patch, followups}
```

浏览器页面 `/desk` 走同一条路，只是入口是 `/desk/api/query`，状态由页面每轮回传。

**登录接力**

```
会话过期 ─▶ 运行层按图谱 auth 重新登录
              ├─ 图片验证码：先自动识别；失败 ─▶ 原图给用户 ─▶ 用户输入 ─▶ 原样填回
              ├─ 短信码：提示用户 ─▶ 用户输入 ─▶ 原样填回（实时）
              └─ 滑块 / 扫码：把那块画面给用户操作        ← 未实现，见 T6
```

## 3. 部署现状（2026-11-20 实地查看）

- 服务器：一台 4090 D。VoiceLab 四个服务只监听本机：编排 8040、识别 8030、合成 8031（按需启动）、本地模型 8050（llama.cpp，Qwen3；VoiceLab 文档写的是 4B-Q4）。
- 运行层：`~/projects/snxt-query`，systemd 用户服务 `snxt-query`，端口 8790。**跑的还是旧版代码**。
- VoiceLab 里登记为 agent `snxt_deduction`，`type: http`，指向 `/voice/handle`。
- 公网入口：Cloudflare 隧道（`tradesitecloud.com` 下已有若干子域名，`me.` 指向另一个服务，不要动）。**已定：给运行层另开一个子域名，名字待定，尚未配置。**
- 部署方式：在开发机上运行仓库外的 `deploy_server.sh`（打包 → scp → 解包 → 重启服务 → 向 VoiceLab 注册 agent）。

**已知的线上问题**

- VoiceLab 里登记的口令是空的，而运行层的 `/voice/handle` 要口令（不带返回 401），所以语音链路按当前配置调不通。部署脚本已修（口令改为在服务器端读取），**重新部署一次后才生效**。
- 运行层监听 `0.0.0.0:8790`，而 `/desk/api/*` 不需要口令。见 T0。

## 4. 已经做了的

- 浅色会话页：语音球、输入框、示例问法；回答是一句结论 + 图或表 + 可点的后续问题；过程默认收起。
- 多轮：每轮回传状态，「那 12 月呢」「明细呢」「那发货呢」可连续追问；没听懂不清空上下文。
- 图谱里的能力带 `examples` / `followups` / `metrics`，页面和语音都从图谱读，页面不写死业务词。
- 管理页：节点连线图谱、导入外部图谱并校验、服务现状。
- 只读检查接到了真正发往业务系统的请求上。
- 清掉了本地探索、浏览器抓取、假的「生成系统」接口、写死的账号兜底、过期文档。
- 定了图谱标准 v1 和给外部模型的探索说明（**只有文档，运行层还没按它实现**）。
